# GeoIP reader comparison evidence

This is an offline compatibility experiment, not a dashboard patch. See
`../../restart-dashboard-geoip-reader.md` for the decision and remaining scope.

- `source-baseline.json`: the dashboard commit/file hashes before the experiment
  and the preserved 1,007 efsn source/module hashes.
- `*-metadata.json`, `acquisition.json`: public npm metadata for the selected
  reader and the two wrappers considered. Only `mmdb-lib` is loaded in the MMDB
  experiment. It has no runtime dependencies. `advisories.json` is the separate
  package-specific registry response.
- `fixture-commit.json`, `fixture-tree.json`, `fixtures.json`: MaxMind test-source
  commit and exact downloaded file provenance. No production geography data.
- `fetch-sources.py`, `fetch-fixtures.py`: retrieve the pinned package and named
  fixtures into contained scratch space, verify package integrity/Git blobs,
  and cap download and expansion sizes. No package install scripts run.
- `prepare-cases.py`, `expectations.json`: create expected records independently
  with Python `ipaddress` before Node runs. Published JSON supplies City values;
  `pkg/writer/maxmind.go` supplies the IPv6 range and prefix-value rule. The
  generated JSON remains in scratch; its hash and size are recorded.
- `compare.cjs`, `prototype.cjs`, `run.py`, `run-1/`, `reader-results.json`:
  3,007 exact raw-record cases plus seven lookup and eight mapping cases. The
  prototype has a fixed synthetic test file and is deliberately not a service
  configuration loader.
- `prepare-legacy.py`, `legacy-patch.json`, `legacy.cjs`: patch only scratch
  copies of the previous reader, then compare the known independently encoded
  NO/SE single-address fixture and surrounding gaps. No installed dependency
  files are changed.
- `model.cjs`, `run-comparison.py`, `comparison-1/`: compile an in-memory node
  model with the proposed dependency substitution and mapped-IP handling, then
  use the real snapshot mapper. Record the unresolved country-only flag loss.
- `verify.py`, `verification.json`: verify results, source preservation and
  downloaded fixtures/packages after the experiment.

Reproduction uses the existing `FusionRehearsal` distro and Linux Node 24.21.0.
Paths are relative to this bundle except that the recorded runtime and Windows
Git environment are local to this workstation. Fresh-run scripts intentionally
refuse to replace an existing candidate directory or result directory; preserve
previous results and choose a fresh workspace for another run. The legacy
comparison uses the tiny precision fixture generated by the preceding
`restart-dashboard-geoip-validation-2026-10-04/run-validation.py` investigation.

Public source acquisition and the advisory request require network access;
the reader/model comparisons use local files only. Individual Node processes
have a 30- or 45-second external deadline and 128 MiB V8 old-space limit. No
malformed-file resource-exhaustion fixtures are downloaded or executed. Test
database contents are synthetic and must never be installed as launch data.

Upstream fixture license/provenance: the downloaded `LICENSE-MIT` is recorded
in `fixtures.json`; binaries and source JSON remain under ignored scratch and
can be retrieved from their immutable URLs. The npm reader's MIT license is
included in its integrity-checked tarball.
